1 · The motion law: line search against per-pair floors

The old solver integrated a spring/projection field and asked DRC afterwards; any model error became a violation. Creep inverts the authority: a unit (footprint assembly, trace node, via — trace segments and vias are first-class movers, in alternating passes with the parts) proposes a step, and a line search keeps the largest fraction whose margins stay above per-pair floors. α = 0 is a legal answer: no room, no move.

creep.py (new) — the whole architecture in three functions
+ def line_search(gen_at):
+     clamps = []
+     if feasible(gen_at(1.0), clamps):
+         return 1.0, []
+     lo, hi = 0.0, 1.0
+     for _ in range(6):                      # bisect to the last feasible fraction
+         mid = (lo + hi) / 2
+         if feasible(gen_at(mid), None): lo = mid
+         else:                           hi = mid
+     return lo, clamps                       # clamps = exactly which pairs blocked, for pressure + worklist
  
+ def floor_of(key):                          # rule + 15µm for new pairs;
+     g = CRT_GUARD if key[0] == 'CY' else GUARD
+     f = gf.get(key)                         # shipped margin for pairs the shipped board
+     return g if f is None else min(f, g)    # held at/below rule+0.02 — legal by proof of shipping

Blocked movers deposit pressure on the dynamic copper that clamped them; pressured copper yields in the copper passes as far as its floors allow. Packed corridors creep like a traffic jam instead of shearing — which is precisely what killed cycles 1–3 at the Net-(U18-A)↔GND cluster: the field sheared it 17µm past the rule at s=0.02. Creep's first checkpoint at s=0.106 is clean there.

2 · Per-polygon-edge floors (the 1.2µm leak the gate caught)

Two gate rounds exposed a subtle unsoundness in margin grandfathering: R92's pad, pressed against two GND stubs and sliding past them, arrived 1.2µm under the rule while the model swore the margin was held. The contact point was walking around the pad polygon — and the polygonization bias jumps between edges, so one chain-level floor let it walk through the jumps for free. Within a single straight edge, line-to-line distance is exact; so the fix keys every copper margin by polygon edge:

+     lets a sliding contact walk the perimeter through the bias jumps (the
+     R92 leak), per-edge floors re-guard every new edge it reaches."""

Feeding this are true pad shapes: graft's obstacle pads are 4-point bounding rects, up to ~0.4mm larger than the real copper with position-dependent bias. The new padgeom.py dumps KiCad's own effective polygons (inflated 5µm outward — they're inscribed), the per-pad local clearances (H3/H4 mounting holes carry a 1.4mm override the model never knew — the gate caught /I2C_SDA drifting to 1.394mm from H4), and the NPTH flag (hole rules only, no phantom copper).

3 · Attachment: connectivity as a constraint (the airwire leak)

The first clean-clearance run still went unconnected at s≈0.5: D24 slid off a same-net stub that ends exactly at its pad edge. Graft's drag set only catches copper whose endpoint lands on a moving pad; contacts that are purely geometric — T-junctions, stubs under pads — were invisible, and the model happily disconnected them. Now every same-net pair that touches on the shipped board is an attachment: it must keep ≥20µm of copper overlap, max-aggregated so one surviving contact point is enough. GND is exempt (the pour re-stitches it on refill).
